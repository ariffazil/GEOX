## 4. Integration Protocols

### 4.1. arifFlow Receipt Streaming (`/var/lib/arifflow/receipts.jsonl`)
Whenever a GEOX observation or computation step executes, it issues an immutable receipt formatted to the canonical arifFlow schema:
```json
{
  "receipt_id": "c1f76cf6-...",
  "created_at": "2026-11-03T10:15:30.123Z",
  "actor_id": "geox:worker",
  "step_type": "Observe",
  "risk_class": "T0Observe",
  "routed_organ": "GEOX",
  "jcs_body_hash": "2f4b09...",
  "cost_ns": 15000000,
  "payload": {
    "tool": "geox_observe",
    "event": "OBSERVE_COMPLETE",
    "organ": "GEOX",
    "status": "SUCCESS"
  }
}
```
Receipts append under POSIX `flock` to guarantee concurrent safety without blocking caller pipelines.

### 4.2. Independent Witnessing via FRAME (`:18085`)
To avoid self-referential bias (**Gödel Lock**), GEOX candidate geometries and fault extractions submit witness requests to the FRAME organ:
```
GEOX (Proposer) ───[ POST /witness ]───> FRAME :18085 (Independent Observer)
                                                │
                                                ▼
                                   Multi-Organ Consensus (10 Organs)
```
If the live FRAME HTTP endpoint is unreachable, the request is recorded in `/root/chron/data/frame_requests.jsonl` with status `RECORDED_PENDING_FRAME` for asynchronous consensus.

### 4.3. Bitemporal Anchoring in CHRON
Subsurface horizons, reservoir tops, and structural hypotheses are registered in the CHRON bitemporal store:
- `assertion_time`: When the model or agent generated the claim.
- `valid_from`: The geological deep-time epoch or observational snapshot to which the claim applies.

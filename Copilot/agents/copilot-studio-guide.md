Creating a GEOX Agent in Microsoft Copilot Studio for Kinabalu Basin (Aligned with arifOS)
Building a GEOX agent (a geoscience AI assistant) within your Enterprise Content Management System (ECMS) using Microsoft Copilot Studio involves several steps, from setting up the custom agent, adding domain-specific knowledge (the Kinabalu Basin “knowledge artifact”), to aligning the agent’s behavior with arifOS (Arif’s constitutional AI kernel). 1. Step-by-Step: Creating a Custom Agent in Microsoft Copilot Studio
Prerequisites & Setup: Make sure you have access to Microsoft Copilot Studio, which is part of the Power Platform environment (often integrated with your Microsoft 365 tenant). You’ll need an appropriate license or preview access for Copilot Studio, and a Power Platform environment with Dataverse where the agent will reside. If you’re using a trial or preview, note that publishing options may be limited without a full license (trial users can create and test agents, but might only publish to a demo site unless a suitable license is in place). [learn.microsoft.com]
Step 1 – Access Copilot Studio: Sign in to Microsoft Copilot Studio using your work or school account associated with your ECMS (e.g. your Microsoft 365 account). Once signed in, navigate to the Copilot Studio Home or Agents section. If it’s your first time, you might see a prompt to “Describe what your agent needs to do.” (If this prompt doesn’t appear, your environment may require a manual setup – in that case, click Create an agent to start a new project.) [learn.microsoft.com]
Step 2 – Create a New Agent: Click “Create an agent” and provide a brief description of the agent’s purpose in plain language. For example, you might write “An AI assistant that helps geoscientists find information about the Kinabalu Basin from our internal knowledge base”. Copilot Studio will use this description to generate an initial agent framework. Give the agent a name that reflects its role (e.g. “Kinabalu Basin GEOX Assistant”) and verify the primary language (you can choose or change the language, solution, and schema name if needed). After a few moments, the agent will be provisioned and you’ll be taken to the agent’s Overview page. [learn.microsoft.com]
Step 3 – Configure Agent Basics: On the agent’s Overview (or Details) page, refine the basic settings:


Name & Description: Click Edit in the Details section to adjust the agent’s name (up to 42 characters, avoiding special characters like < or >). Update the description if necessary, to clearly define the agent’s purpose (up to 1,024 characters). [learn.microsoft.com], [learn.microsoft.com]


Instructions (System Prompt): In the Instructions section, Copilot Studio may have generated a default system prompt based on your description. Select Edit to review and refine these instructions. Ensure the instructions cover the agent’s domain and desired tone. For example, you might instruct the agent to respond in a professional but user-friendly tone suitable for geoscientists and to focus on topics related to the Kinabalu Basin project. Keep instructions concise and under the 8,000-character limit. [learn.microsoft.com]
Best Practice: Write clear instructions that define the agent’s role, scope, and style. For instance: “You are a GEOX Copilot assisting with Kinabalu Basin geoscience queries. You provide accurate, detailed answers based on our internal knowledge base and arifOS principles, using a professional and helpful tone.” This ensures the agent stays on-topic and maintains the desired persona.


Step 4 – Add Suggested Prompts (Optional): If your agent will be used in Microsoft Teams or Microsoft 365 apps, you can configure up to 10 suggested user prompts to help users get started. On the Overview page, find Suggested prompts and add common questions or tasks (e.g., “How do I assess reservoir quality in Kinabalu Basin?”, “Show me the stratigraphic framework for Kinabalu Basin”, etc.). These will appear on the agent’s welcome screen and can guide users in exploring the agent’s capabilities. (Note: Suggested prompts aren’t visible in the test chat within Copilot Studio, but they will appear to end users in Teams or other channels.) [learn.microsoft.com]
Step 5 – Test and Refine the Agent: Use the built-in Test your agent chat panel in Copilot Studio to interact with your agent and see how it responds. At this stage, with no external knowledge added yet, the agent might rely solely on the instructions or any content you add. Try asking a sample question (e.g. “What is the Kinabalu Basin?”) to see how it responds. Likely, it won’t have a complete answer until we add the knowledge base in the next step. Take this opportunity to adjust the instructions or add additional internal knowledge as needed: [learn.microsoft.com]

To change the agent’s introductory message (the greeting shown to users at the start of a conversation), click the message in the test panel and edit it in the Conversation Start topic. For example, you can have it introduce itself as “Hello, I’m the GEOX Copilot for Kinabalu Basin projects. I can assist with questions on geology, data, and reports related to the Kinabalu Basin. How can I help you today?” Then save and Start a new test session to verify the updated greeting. [learn.microsoft.com], [learn.microsoft.com]
If the agent’s answers seem off-target, consider fine-tuning its Instructions or adding more knowledge sources (next step) to give it the necessary context. For instance, you might emphasize in the instructions that the agent should only answer using verified Kinabalu Basin documents (to avoid hallucinations and keep answers focused).

Step 6 – [Next: Add Knowledge] – Now that the agent’s basics are set up, proceed to integrate your “knowledge artifact” (the Kinabalu Basin content from your Microsoft 365 chat or SharePoint site) as a knowledge source.

Prefer answers that are confirmed by multiple sources.” [arifos.ari...-fazil.com]

4. Deployment in ECMS and Enterprise Considerations
With your GEOX agent built and enriched with knowledge and governance, the final steps are deploying it within your Enterprise Content Management System and ensuring it operates effectively in your organizational context. Here’s how to proceed and what to consider:
A. Publishing and Deployment Options: In Copilot Studio, navigate to the Publish menu for your agent. If you have a proper license or are in a supported environment, you can publish the agent to various channels:

Demo Website: For initial testing or demo purposes, Copilot Studio allows publishing the agent to a web demo. Simply click Publish on the agent, confirm publishing, and then use the “Go to demo website” option to open a web chat interface for the agent. You can share this URL internally to gather feedback during development. (Keep in mind that if you’re on a trial, you may be limited to the demo site and not full deployment.) [learn.microsoft.com]
SharePoint (ECMS) Integration: To bring the agent into your ECMS, the ideal approach is to deploy it to a SharePoint site, since your enterprise likely uses SharePoint as part of its ECMS. Copilot Studio supports adding SharePoint as a deployment channel. After the agent is published, go to the Channels tab in Copilot Studio, select the SharePoint channel, and specify the target SharePoint site (for example, a site related to the Kinabalu Basin project or a team site where your users collaborate). Click Deploy to add the agent to that site. Once deployed, the agent can appear as a Copilot (bot) interface embedded in the SharePoint page, allowing users of that site to chat with the GEOX agent directly within the ECMS environment. [learn.microsoft.com]

Alternatively, Copilot Studio also allows deploying agents to Microsoft Teams or other channels. If your team uses Teams extensively, you could add the agent as a Teams app or bot (via the Teams channel in Copilot Studio). Users would then be able to chat with the GEOX agent in a Teams conversation or channel. Choose the channel that best fits your users’ workflow – the functionality of the agent remains the same, but accessibility differs (SharePoint for intranet web access vs. Teams for chat interface).
Note on Permissions & Access: When deploying to a SharePoint channel, the agent will respect your SharePoint’s access controls. Only users who have access to the site (and to the documents in the knowledge base) will be able to retrieve that content via the agent. This ensures that sensitive Kinabalu Basin data remains secure – if a user isn’t permitted to view a certain document in SharePoint, the agent will not surface that document’s content for them. Before deployment, double-check that the SharePoint site and library permissions are correctly set for your intended audience. [citizendev...per365.com]
